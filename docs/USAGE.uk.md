# Як користуватися claude-toolkit

🇬🇧 [English version](USAGE.md)

## 1. Щоденні команди

| Пишеш | Що відбувається |
|---|---|
| `/task <будь-що>` | Claude визначає, як виконати запит (сам / агент / скіл / паралельно / підтікети), показує рішення у 2–3 рядках і виконує. Підтікети в Linear створює лише після твого «так». |
| `/pickup CDP-123` | Читає тікет у Linear (+ пов'язані Sentry/Figma) → переказує задачу → створює гілку → реалізує → запускає локальні перевірки (`yarn build` у cdp2) → віддає commit message, текст PR і коментар для Linear. У Linear пише / переводить в In Review лише після «так». |
| *будь-що звичайними словами* | Правила роутингу з `~/.claude/CLAUDE.md` діють і так: номер тікета → спершу Linear, посилання на Sentry → спершу Sentry, широкий пошук → агент Explore, незалежні частини → паралельні агенти. |
| `/sentry-sweep [24h\|7d]` | Знаходить цей проєкт у Sentry, лагодить термінові й найчастіші помилки, повертає список змін + commit message. Потрібен логін у Sentry (`/mcp`). |
| `/slack-scan [today\|3d\|this week] [#канал]` | Шукає у Slack проблеми, які можна виправити в цьому репо, показує список і питає, що фіксити. |

## 1b. Агенти (у кожному проєкті)

Claude обирає їх сам (правила роутингу); можна й назвати: «спитай neckbeard, як працює auth».

| Агент | Для чого | Змінює код? |
|---|---|---|
| `neckbeard` | «Як працює X?» — відповідь із коду з посиланнями `file:line` | ні |
| `sidequest` | Полагодити сторонній баг посеред фічі, не витрачаючи основний контекст | так, без комітів |
| `rules-review` | Перевірити диф на правила з CLAUDE.md проєкту перед commit message | ні |
| `browser-verify` | Прокликати зміну на localhost у Chrome: рендер, консоль, мережа | ні |
| `sentry-fix` | Працює за `/sentry-sweep` | так, без комітів |
| `slack-scout` | Працює за `/slack-scan` | ні |

**Агент проєкту з тим самим іменем має пріоритет.** У cdp2-frontend є власні, детальніші версії всіх шести (плюс `ds-docs` і команди `/ticket`, `/commit-msg`), тож там працюють вони; в усіх інших проєктах — ці.

## 2. Команди в терміналі

| Команда | Що робить |
|---|---|
| `crc` | Claude з Remote Control (керуєш з телефона). |
| `crcb` | Те саме, сесія називається `<папка>:<гілка>`. |
| `wt CDP-123 [slug]` | Новий worktree `../<repo>-wt/cdp-123[-slug]` + гілка + залежності + Claude з `/pickup CDP-123`. Запусти в кількох терміналах — кілька тікетів паралельно. `WT_BASE=origin/dev wt …` — гілка від dev. |
| `wt-clean` | Показує змерджені чисті worktree; `wt-clean --yes` видаляє їх. |
| `claude-hook-enable` | У репо: вирізає атрибуцію Claude з кожного коміту. |
| `toolkit-sync "msg"` | Коміт + пуш усіх змін тулкіта. |

## 3. З телефона

- **Ноут увімкнений:** на ноуті `crc` (або `wt CDP-123`) → додаток Claude → **Code** → відкрий сесію. Ноут не має засинати.
- **Ноут вимкнений:** додаток Claude → **Code** → New session → обери репо. Тулкіт підтягується через setup script (README).

Детальніше: [MOBILE.md](../MOBILE.md).

## 4. Як змінювати налаштування

Просто скажи Claude, що змінити, з будь-якого проєкту. Він сам вирішить, куди це покласти:

| Зміна стосується… | Куди йде | Коміт |
|---|---|---|
| лише одного проєкту (його правил, агентів, Sentry/Slack) | `.claude/` цього проєкту | ти, разом з роботою в проєкті |
| усіх проєктів | `~/code/claude-toolkit/` | **Claude сам комітить і пушить** (`toolkit-sync`) |

Зміни в наявних файлах тулкіта діють одразу (це симлінки). **Новий** файл команди чи агента — один раз `~/code/claude-toolkit/install.sh` на кожній машині.

## 5. Інша машина

```bash
git clone git@github.com:chabanroman/claude-toolkit.git ~/code/claude-toolkit
~/code/claude-toolkit/install.sh && source ~/.zshrc
```
Оновлення: `git -C ~/code/claude-toolkit pull`.

## 6. Разові ручні кроки

- Sentry: `/mcp` → «claude.ai Sentry» → Authenticate.
- Хмарні сесії: додай setup script з README на claude.ai/code.
- За бажанням: `brew install gh && gh auth login`, якщо Claude має сам відкривати PR.
